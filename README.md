# Карьерная карта — документация проекта
Версия 1.0 · 16 октября 2026 · язык документации: русский.

Это проектная документация и визуальные референсы, не отчёт о готовой реализации. Сервис охватывает все направления IT. QA используется только как пример. Не утверждается соответствие всем формальным стандартам: SDD — процесс, а SAD — архитектурное описание. Комплект использует практики spec-first, ADR, arc42, C4 и контрактного проектирования, адаптированные к студенческому MVP.

Откройте START_HERE.html в браузере для чтения всех документов и просмотра экранов без дополнительных программ. Диаграммы Mermaid в нём показаны как исходный текст; для рендеринга используйте совместимый Markdown-редактор.

## Структура
- docs — продукт, требования, архитектура, данные, правила, UX, процесс, проверки.
- specs — пофункциональные spec.md, plan.md, tasks.md.
- contracts/openapi.yaml — предлагаемый HTTP API, OpenAPI 3.1.1.
- schemas/domain.schema.json — модель обмена, JSON Schema 2020-12.
- examples — согласованные синтетические записи и примеры расчёта.
- adr — журнал архитектурных решений со статусом Proposed.
- quality — трассировка требований, сценарии и проверка комплекта.
- design — PNG, токены, тексты и промпты генерации.
- AGENTS.md — правила для будущего coding-agent.

[План наполнения всех IT-направлений](docs/17_content_workplan.md).

## Статусы решений
CONFIRMED — пользователь прямо задал это в обсуждении. PROPOSED — конкретное предложение для старта реализации. OPEN — отсутствуют необходимые сведения. IMPLEMENTED и VERIFIED не используются для приложения: код приложения и инфраструктура здесь не создавались. Проверки пакета относятся к документации и примерам.

## Объём и ограничения
Все IT-направления входят в модель продукта; фактическое покрытие каталога, критериев и проверок явно хранится по каждой роли. Недостаток контента не маскируется подтверждёнными оценками. Архив не содержит скачанные полные ESCO/O*NET, лицензированный корпус SFIA, персональные данные, реальные ключи API и production-конфигурацию.
PNG являются растрами: их можно вставить в Figma, но нельзя автоматически получить редактируемые компоненты. Точные тексты, состояния и формулы определяются спецификациями, а не случайными деталями изображений.
