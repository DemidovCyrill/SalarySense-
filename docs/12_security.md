# Безопасность и приватность
## Границы доверия
Браузер недоверенный; сервер определяет владельца по сессии. Внешние вакансии и источники — недоверенные данные. Модель не является механизмом авторизации. Подписанная/закрытая среда должна проверять доступ до выдачи API и файлов.

## Угрозы и меры
| Угроза | Мера | Проверка |
|---|---|---|
| Чужой профиль по ID | Ownership check для каждого объекта; server-resolved owner | T16 |
| Утечка ключей тестов | PublicQuestion отдельный DTO; server-only key; корпус не содержит ответы | Contract negative check |
| Prompt injection | Источники как данные; allowlist инструментов/ссылок; запрет изменения расчёта моделью | T13 |
| XSS из вакансии | Очистка HTML, escape, запрет unsafe rendering; CSP | Вредоносный fixture |
| SSRF при импорте | Allowlist доменов, запрет local/private IP и redirect-обходов | Security integration |
| Массовые вызовы LLM | Rate limits по session/IP, token budget, timeout | Load/budget suite |
| Кража сессии | HTTPS, Secure/HttpOnly/SameSite cookie, CSRF на мутациях | Browser/API tests |
| Подмена версии ответа | Оптимистическая блокировка, frozen bank version | T14,T15 |
| Секреты в клиенте | Только серверный secret store/env; проверка bundle/логов | Release check |

## Сессия — PROPOSED
Гостевая защищённая cookie-сессия, ограниченная временем; без cross-device promise. session endpoint выдаёт CSRF token; mutating API требует X-CSRF-Token, включая данные профиля и ответы. Session creation защищена Origin check и SameSite; rate limit отдельно. При переходе к аккаунтам нужна отдельная spec миграции ownership.

## Минимизация
Не запрашивать резюме, паспорт, личные банковские сведения. Профиль не публичен. Для объяснения передавать только skill/evidence scope и нормализованные требования без контактов. Перед live провайдером согласовать регион, retention и допустимость передачи. Нет утверждения о юридической сертификации сервиса; требования персональных данных уточняются под выбранный режим запуска.
Retention и удаление в docs/05_data_model.md. Тексты ответов не писать в общие логи, трассировки промптов маскировать и ограничивать доступ. Удаление из бэкапов выполняется по раскрытому циклу.
