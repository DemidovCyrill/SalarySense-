# Spec-Driven Development
SDD здесь означает разработку по спецификациям, а не просьбу модели «сделать весь сайт». SAD — отдельный документ об архитектуре. Процесс совместим с Spec Kit, но не требует определённой версии CLI.

## Конституция проекта
1. Все IT-направления остаются в продуктовом охвате.
2. Отметка опыта не подтверждает знание; тест не подтверждает стаж или руководство.
3. Числовой результат воспроизводим и вычисляется кодом.
4. Все выводы имеют scope, источник и версию либо ограничение.
5. Demo/live, отсутствие и непроверенность не смешиваются.
6. Ключи ответов и чужие данные не входят в контекст модели.
7. Нет выдуманных зарплат, ссылок, достижений и автоматических откликов.
8. Изменение поведения сначала отражается в spec/контракте.

## Цикл функции
Specify: сценарий, границы, FR и acceptance criteria. Clarify: закрыть блокирующие вопросы, неблокирующие допущения записать Proposed. Plan: компоненты, контракт, данные, риски. Tasks: маленькие проверяемые изменения. Implement: одна законченная вертикальная часть. Verify/Converge: сравнить реализацию со spec, тестами и UX; не считать зелёную сборку доказательством правильности содержания.
Проверки и человеческое ревью входят в цикл. Параллельная работа разрешается процессом команды только после определения контрактов; этот архив сам не запускает агентов.

## Определение Ready
Известен владелец, spec без блокирующих OPEN, FR и тестовые примеры связаны, данные и лицензии доступны или demo явно выбран, контракт валиден.
## Определение Done
Критерии приёмки выполнены; unit/contract/integration/E2E по риску; проверено отображение; нет утечки ответов; обновлены docs/ADR/traceability; код reviewed; ограничения раскрыты. Для AI-функции сохранён eval report на фиксированном test наборе.

## Изменения
Change request: причина, затронутые FR/spec/API/data, обратная совместимость, миграция, проверки, статус решения. Breaking API повышает версию; обновление criteria не перезаписывает историю. При конфликте источником требований служат CONFIRMED-решения и последняя утверждённая spec; PNG не заменяет контракт.

## Работа с coding-agent
Загрузить README, AGENTS, конкретный spec и связанные contracts; не передавать весь архив без задачи. Попросить перечислить неоднозначности и ограничения, затем реализовать задачу с проверки. Секреты не вставлять в чат. Generated code требует тех же проверок, что и ручной.
