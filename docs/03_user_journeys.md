# Пользовательские сценарии
## Роли
Посетитель/владелец профиля; редактор контента; проверяющий контент; оператор. Один участник команды может совмещать роли, но ревью вопросов перед публикацией должно быть независимым от генерации.

## UC01: первый полезный результат
Предусловие: опубликован каталог, доступен live или явно обозначенный demo snapshot.
Выбор направления → условий → каталога → отметка навыков → «Посмотреть рынок» → карточки вакансий.
Постусловие: профиль сохранён, оценки помечены предварительными, знаменатель требований известен.
Альтернативы: ничего не отмечено — показать рынок без персонального процента; нет вакансий — empty с сохранением фильтров; критерии роли draft — рынок доступен, подтверждённый уровень скрыт.

## UC02: уточнение навыка
Выбрать навык → показать scope, время и ограничения → старт версии теста → ответы/«не знаю» → завершение → результат.
Автосохранение после каждого принятого ответа. Потеря соединения не считается неверным ответом. «Не знаю» считается нулём по проверяемому вопросу, но не доказательством отсутствия всего навыка.
Параллельная вкладка не может завершить попытку второй раз. Повторный запрос завершения возвращает тот же result_id.
Смена версии банка не меняет уже начатую попытку. Удалённый вопрос в активной версии обрабатывается отдельным статусом review_required, а не молчаливой заменой.

## UC03: выбор вакансии
Список → фильтр → разбор → раскрыть требование → посмотреть исходный фрагмент и критерий → при необходимости проверить навык → вернуться.
Нет URL в demo — кнопка отключена с пояснением. Архивная вакансия помечена и исключена из активного списка по умолчанию. Неуказанный грейд работодателя не подменяется выводом модели.

## UC04: письмо
Разбор → «Создать черновик» → список фактов → редактирование → копирование.
Факты имеют evidence_id. Заявленный опыт допустим, но не усиливается до проверенного. Имя и контакты пользователь вводит сам при необходимости. Автоматической отправки нет.

## UC05: изменение направления
Общие навыки остаются в профиле; роли имеют собственные критерии и веса. Профиль QA нельзя автоматически превратить в профиль Product Manager. Пересчитываются уровни, вакансии и scope проверки.

## UC06: senior / lead
Показывать отдельно знание, практику, самостоятельность, ответственность, влияние. Если есть только тесты, показывать покрытие знаний, а не аттестацию senior/lead. Кейс требует собственного рубрикатора и ревью; самоописанный опыт помечается как self_reported.

## UC07: удаление
Пользователь подтверждает сброс своего профиля → сервер удаляет профиль, попытки и персональные объяснения → cookie инвалидируется. Обезличенная агрегированная статистика допустима только при заранее раскрытых правилах.
