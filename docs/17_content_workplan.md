# План контента для всех направлений IT
Статус: Proposed, объём уточняется командой. Список групп в product brief сохраняет общий охват.

## Карточка готовности каждой роли
Указать владельца/проверяющего, taxonomy mapping, каталог технологий, список scopes, источники/права, модели intern/junior/middle/senior, критерии leadership отдельно, число проверенных вопросов/кейсов, coverage и известные пробелы. Нельзя использовать один QA-вопрос для оценки другой профессии из-за общих слов.

## Порядок наполнения
1. Согласовать группы/подроли всего IT и связать общие навыки стабильными ID.
2. Импортировать релевантные сущности ESCO в staging; дополнить современными технологиями по вакансиям, проверяя термины.
3. По каждой группе собрать первичные источники критериев. Одна компания не равна стандарту рынка; сохранить разницу моделей.
4. Создать общие рубрики самостоятельности, практики, ответственности; роли добавляют свои наблюдаемые признаки.
5. Подготовить вопросы по отдельным scopes; coverage таблица определяет, что можно обещать пользователю.
6. Провести ревью и опубликовать версию; непроверенные области остаются видимыми как draft/absent.

## Оценка объёма
Количество карточек: подроли × компетенции × применимые уровни до переиспользования. Пример 20×10×4=800 — арифметический ориентир, не готовый корпус. Число вопросов определяется покрытием scopes и вариантами сложности, а не количеством красивых карточек. Генерация ИИ даёт черновики; реальный bottleneck — ревью и проверка корректности.

## Калибровка
Не переносить корпоративные пороги автоматически. Для выбранной рубрики несколько специалистов независимо размечают кейсы; расхождения обсуждаются, правила уточняются. До достаточных данных вывод обозначается как ориентир/предварительный. Оценки разных ролей нельзя напрямую сравнивать по одному числу.
