# Стратегия проверок и приёмка
Это план будущих испытаний приложения. Реально выполненные проверки комплекта находятся в quality/validation_report.json.

## Уровни
Unit: чистая функция score, scopes, rounding, null salary, aliases, quartiles, фильтры. Contract: DTO, OpenAPI, отсутствие answer keys. Integration: DB ownership, попытки, worker staging/publish/rollback, retrieval published-only. E2E: выбор роли → сохранение → проверка → рынок → вакансия → объяснение → письмо. Visual: согласованные desktop/mobile состояния, длинные названия и empty/error. Content: независимое ревью вопросов и критериев. Нагрузочные: NFR03 на объявленной конфигурации.

## Минимальная регрессия
| ID | Сценарий | Ожидание |
|---|---|---|
| T01 | Любое IT-направление без тестов | Каталог/рынок доступны; coverage виден; нет подтверждённого грейда |
| T02 | Только самоотметка | Verified evidence не создаётся |
| T03 | Проверка 3/4 базовых вопросов | Scope basic, не senior/lead |
| T04 | Незнакомый alias | Ambiguous/unknown, а не выдуманный ID |
| T05 | Квиз basic vs требование architecture | Не засчитывается как закрытая архитектура |
| T06 | Score fixture | 63% профиль и 45% подтверждено |
| T07 | Σw=0 | null + insufficient_data |
| T08 | Hard constraint fail | Явная причина; skill score не маскирует препятствие |
| T09 | Нет salary / одна граница | Не входит в основную midpoint медиану |
| T10 | Разные gross/net/currency | Не объединяются в одну цифру |
| T11 | Малый N | Недостаточно данных, N виден |
| T12 | Нет RAG-контекста | insufficient_data без выдуманной ссылки |
| T13 | Инструкция в описании вакансии | Не меняет системные правила/скоринг |
| T14 | Смена profile revision | Старый результат помечен, новый расчёт по новой версии |
| T15 | Повтор finish | Тот же result_id, без дубликата evidence |
| T16 | Чужой assessment/match ID | 404 или 403 по единой политике, данные не раскрываются |
| T17 | Провайдер недоступен | Числа и источник доступны; explanation partial |
| T18 | Удаление профиля | Сессия инвалидирована, персональные записи удалены |
| T19 | Demo вакансия | Нет активного перехода к выдуманному источнику |
| T20 | Письмо с отсутствующим достижением | Числовое достижение не выдумывается |

## Инварианты и property checks
0≤C≤P≤100; обязательный незакрытый skill виден; перестановка требований не меняет score; дубликат импорта не удваивает выборку; форматирование не меняет source excerpt; новая версия не меняет старый snapshot; отсутствие проверки не считается отрицанием опыта.

## AI-eval
См. docs/06_RAG_and_content.md, examples/rag_eval_cases.jsonl. Показатели качества на test split, не только dev. Сравнить no-RAG, keyword baseline и предложенный retrieval при одинаковых вопросах; оценить поддержанность claims, relevance и корректность отказов. LLM-as-judge можно использовать как помощник, не единственный критерий.

## Приёмка выпуска
Критические privacy/answer-leak дефекты отсутствуют; P0 E2E пройден; FR traceability полная; покрытие ролей видно; score воспроизводим; качество RAG измерено; UX проверен на 390 px и desktop; стоимость ограничена; публикация приватная. Всё непроверенное явно перечислено в release notes.
