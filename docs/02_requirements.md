# Функциональные и качественные требования
Версия требований 1.0. Все критерии ниже — проектные, не результаты испытаний.
## Функциональные требования
| ID | Функция | Обязательное поведение | Проверяемая приёмка |
|---|---|---|---|
| FR01 | Каталог направлений | Каталог показывает все настроенные IT-роли и coverage_status. | При отсутствии вопросов направление остаётся доступным; проверка помечается недоступной. |
| FR02 | Выбор условий | Сохраняются роль, регион, формат работы. | Изменение фильтров пересчитывает выборку и показывает её параметры. |
| FR03 | Навыки | Категории, поиск, aliases; пункты сохраняются по ID. | Повторное открытие сохраняет выбор; синоним не создаёт дубль. |
| FR04 | Опыт | Для навыка сохраняется самооценка и характер опыта. | Одна отметка не создаёт проверенное доказательство. |
| FR05 | Проверка | Запускается короткая версия банка вопросов по выбранному навыку. | Ответы и ключи недоступны до ответа/завершения по правилам теста. |
| FR06 | Результат | Выдаётся проверенный scope, ошибки, ограничения и дата. | 3 из 4 не становится подтверждением senior или рабочего опыта. |
| FR07 | Уровни | Сравнение с версионированной моделью роли. | При нехватке критериев результат insufficient_data; lead отдельно по ответственности. |
| FR08 | Рынок | Количество вакансий, частота требований, параметры выборки. | Нулевые данные дают empty, а не нулевую зарплату. |
| FR09 | Зарплата | Медиана midpoint и квартильный диапазон для сопоставимых вилок. | Валюта, налоги, период, N и исключения отображаются. |
| FR10 | Вакансии | Фильтры, сортировка, статусы, источник, даты. | Demo, stale и live не смешиваются скрыто. |
| FR11 | Совпадение | Заявленное и проверенное покрытие требований. | Обязательный пробел не компенсируется нерелевантными навыками. |
| FR12 | Объяснение | RAG извлекает подходящие действующие критерии и даёт ссылки. | Без достаточного контекста выдаётся ограничение, а не выдуманный критерий. |
| FR13 | Письмо | Черновик только по разрешённым фактам пользователя. | Нет выдуманных достижений и отправки без действия пользователя. |
| FR14 | Контент | Публикация источников, критериев и вопросов после ревью. | Draft/rejected не попадают в production retrieval. |
| FR15 | Управление профилем | Сброс/удаление данных и понятная область сохранения. | Нельзя прочитать чужой профиль подбором ID. |
| FR16 | Восстановление | После перезагрузки карта и завершённые результаты доступны в сессии. | При смене роли общий навык сохраняется, уровень роли пересчитывается. |

## Нефункциональные требования — PROPOSED
| ID | Требование | Целевой сценарий и проверка |
|---|---|---|
| NFR01 | Объяснимость | Каждый вывод об уровне имеет criterion_id, source_id, версию и тип доказательства либо помечен как неизвестный |
| NFR02 | Воспроизводимость | Тот же профиль, snapshot вакансий и scoring_version дают идентичный числовой результат |
| NFR03 | Производительность | При 20 одновременных сессиях и 10k вакансий p95 обычного API < 1 с без LLM; объяснение p95 < 15 с или контролируемый timeout |
| NFR04 | Доступность | Основной каталог и числовой результат работают при отказе модели; браузеры актуальных стабильных версий фиксируются перед тестом |
| NFR05 | Доступность интерфейса | Клавиатура, видимый фокус, подписи полей, текст помимо цвета; контраст не ниже 4.5:1 для обычного текста |
| NFR06 | Приватность | Гостевой профиль изолирован сессией, серверные секреты не входят в клиент |
| NFR07 | Контент | Для опубликованной карточки обязательны источник, допустимость использования, review_status и версия |
| NFR08 | Наблюдаемость | request_id, время, тип отказа, версии и стоимость вызовов без ответов/секретов в логах |
| NFR09 | Адаптивность | Нет горизонтального скролла страницы при 390 px; таблица меняется на карточки |
| NFR10 | Стоимость | Лимит токенов, запросов и расходов на сессию; budget_config выбирается командой до live-запуска |

## Правила формулировок
Требование с SHALL/«должен» обязательно для приёмки функции. Гипотезы, предлагаемые значения и OPEN-решения не выдаются за согласованные факты. Изменение требования проходит change request и обновляет трассировку.
